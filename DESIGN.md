# Dual Screen Mode design language

Made by slinky.

The logo is the source of truth for the interface. The project should feel like
a friendly Wii U-era utility made by one person who wanted a specific setup to
be easier for other people to try.

## Visual language

- Soft charcoal surfaces with faded-black depth, never pure black everywhere.
- Cobalt and light blue for screens, headings, primary actions, and focus.
- Bright cyan for connections, active states, and small moments of energy.
- Charcoal and blue-gray outlines instead of harsh black borders.
- Rounded hardware-like shapes and generous breathing room.
- Very subtle gradients are okay when they add softness; avoid glossy or neon
  gamer styling.
- Off-white belongs mainly to the hardware in the logo, letting the mark stand
  out against the dark interface.
- The monitor-and-handheld mark should be the main decorative element. Do not
  add unrelated rings, mascots, circuitry, or sci-fi effects.

## Voice

The voice is plainspoken, capable, and a little nostalgic. It should feel like
a useful project made by one person, without making every screen speak in the
first person or sound like a company selling software.

Prefer:

- Wii U GamePad
- DS/3DS bottom screen
- handheld
- two-screen setup
- fiddly parts
- desktop shortcut
- connect with Moonlight
- Made by slinky

Avoid:

- companion screen/device
- ecosystem
- seamless experience
- unlock your potential
- workflow
- gamer-bro or streamer language
- unnecessary Linux/display jargon

## Product promise

Dual Screen Mode does not pretend to invent the underlying technology. It
collects existing tools, guides, and hard-won setup knowledge into one
consistent, repeatable package.

The user-facing promise is simple: set it up once, then use the desktop
shortcut whenever they want a Wii U-style GamePad or a DS-style second screen.

## Audio rule

Audio gets its own setup step. The default is to leave the host computer's
audio alone. If the user chooses handheld or dual audio, save the active output,
volume, and mute state first, then restore that exact state when the mode turns
off. Never silently install audio drivers or change the system default without
an explicit choice.
